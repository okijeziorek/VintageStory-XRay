# Verification against Vintage Story 1.22.3

## Required local files

The build machine must have the exact **Vintage Story 1.22.3** installation available through `VINTAGE_STORY` or `VSPath`.

Required assemblies:

- `VintagestoryAPI.dll`
- `VintagestoryLib.dll`
- `Lib/0Harmony.dll`

## Build

```bash
export VINTAGE_STORY=/path/to/VintageStory
 dotnet build -c Release
```

## Runtime test

1. Install the produced client mod into the local Mods directory.
2. Start a 1.22.3 single-player world.
3. Confirm the mod loads without errors in `client-main.log`.
4. Press **F8**.
5. Verify that terrain becomes translucent rather than inventory, GUI or entity meshes.
6. Move through at least two chunk boundaries.
7. Press **F8** again and verify that the terrain returns to normal.
8. Repeat in a world containing caves and several ore types.

## Safety checks

- No server-side mod installation.
- No block placement/removal.
- No network packets generated by the X-Ray implementation itself.
- No mutation of the original `MeshData` buffers after `AddMeshData` returns.
- No transformation of GUI/item meshes when their call stack does not pass through terrain tessellation.

## Known prototype limitation

The current implementation operates at the combined mesh level. It can make terrain translucent, but it cannot yet reliably preserve only ore blocks as opaque because block identity is no longer directly available at this stage.

The next implementation stage must patch the terrain tessellation routine where a block position and block ID are still available.
